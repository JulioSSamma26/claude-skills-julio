## 1. Qué es ECC realmente

**Qué es.** Un "sistema operativo" de arnés para agentes de código: un plugin de Claude Code (`ecc@ecc`) más adaptadores para Codex, Cursor, OpenCode, Gemini, Kimi, Qwen, Zed y otros. Su ciclo declarado es planificar, probar, implementar, revisar, verificar, recordar y mejorar. El README de esta versión anuncia 72 agentes, 328 skills y 99 comandos "legacy" (las cifras han subido desde las 314/71/98 que tenía Julio en mente).

**Estructura del repo (carpetas que importan):**

| Carpeta | Contenido |
|---|---|
| `agents/` | 72 agentes `.md` con frontmatter (`tools`, `model`). Muchos son revisores por lenguaje (python, go, rust, java, react…) y resolutores de build. Todos empiezan con un bloque "Prompt Defense Baseline". |
| `skills/` | 328 carpetas `SKILL.md`. Mezcla de ECC propio, "community" y algunas Apache-2.0 (p. ej. `inventory-demand-planning`, `returns-reverse-logistics`). |
| `commands/` | ~100 comandos slash (`/plan`, `/checkpoint`, `/save-session`, `/learn`, `/evolve`, `/security-scan`…), en transición a skills. |
| `rules/` | Reglas "siempre cargadas" por lenguaje (`common/`, `python/`, `typescript/`…, 145 archivos) con `paths:` en el frontmatter. |
| `hooks/hooks.json` + `scripts/hooks/*.js` | El runtime de hooks: ~29 entradas sobre PreToolUse, PostToolUse, UserPromptSubmit, PreCompact, SessionStart, Stop y SessionEnd. Todo en Node.js. |
| `scripts/` | Instalador (`install-apply.js`), CLI `ecc`, servidor MCP de memoria (`memory-mcp.mjs`), dashboards, canvas. |
| `mcp-configs/`, `.mcp.json` | Configuraciones MCP de ejemplo (no las leí en detalle). |
| `docs/` (2.192 archivos), `tests/` (672), `docker/` (561), `pi/`, `ecc2/` | Documentación, pruebas, harnesses de instalación en contenedores y un "ECC 2.0" en Rust/otros. |

**Cómo se instala.** Tres caminos, que el propio README pide no mezclar:
1. Asistente: `npx ecc-universal@2.2.3 setup` (Node 18+, Git, Claude Code 2.1+). Elige ámbito (user/project/local) y perfil de hooks (minimal/standard/strict u off).
2. Plugin nativo: `/plugin marketplace add https://github.com/affaan-m/ECC` y `/plugin install ecc@ecc`. Claude Code carga `hooks/hooks.json` del plugin automáticamente.
3. Manual desde un clon: `install.sh` / `install.ps1` → `npm install --ignore-scripts` → `node scripts/install-apply.js`. Hay perfil `minimal` sin hooks y `--skills a,b` para instalar solo algunas.

**Qué toca en la configuración:**
- `~/.claude/skills/<nombre>/` (cada skill directamente ahí), `~/.claude/agents/`, reglas y `~/.claude/scripts/hooks/`.
- `~/.claude/settings.json`: registra sus hooks con IDs propios (dice preservar los del usuario y desinstalar limpio).
- Datos en `~/.claude/` (o `ECC_AGENT_DATA_HOME`): `metrics/costs.jsonl`, resúmenes de sesión, `session-data/`, instintos aprendidos, `package-manager.json`.
- Variables `ECC_*` para perfil, hooks desactivados, tope de contexto inyectado en SessionStart (8.000 caracteres por defecto), instintos inyectados (6, confianza ≥0,7), retención de sesiones (30 días).
- Recomienda en el README cambiar `model` a sonnet, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50` y `CLAUDE_CODE_SUBAGENT_MODEL=haiku` (solo es recomendación, no lo aplica solo).

**Riesgos detectados:**

| Riesgo | Detalle | Gravedad para Julio |
|---|---|---|
| Hooks que ejecutan código en cada herramienta | Cada entrada es un `node -e "<bootstrap>"` que resuelve la raíz del plugin y lanza un script. Hay al menos 3 PreToolUse con matcher `.*` (observación para aprendizaje continuo, hookify, gobierno) y 2 PostToolUse `.*`. Todo corre con los permisos de Julio. | Alta: más latencia, más superficie, y código de terceros en cada llamada. |

| Inyección de contexto | SessionStart inyecta hasta 8.000 caracteres (resúmenes previos + instintos) en cada sesión nueva. | Media: choca con su objetivo de listado mínimo (`skillListingBudgetFraction 0.02`). |
| Red | El instalador usa npm (`npx`, `npm install`); las configs MCP de ejemplo usan `npx` y piden red al primer uso; `mcp-health-check` intenta reconectar servidores MCP. La GitHub App "ECC Tools" / ECC Pro analiza repos en un servicio hospedado (opcional, de pago para privados). | Media; la App es opcional y no debe usarse con nada de Afinia. |
| Telemetría | No vi envío automático: el README dice que nunca sube diagnósticos solo (`ecc feedback` es manual) y `cost-tracker.js` escribe en `~/.claude/metrics/` sin llamadas de red (revisé el script). `insaits-security-monitor` es un monitor Python de terceros, **opt-in** (`ECC_ENABLE_INSAITS`); no leí el `.py`. | Baja, con la salvedad de lo no leído. |
| Dependencias | 5 dependencias npm directas fijadas (`@iarna/toml`, `ajv`, `js-yaml`, `sql.js`, `zod`). El instalador usa `--ignore-scripts` (bien). | Baja. |
| Suplantación | `SECURITY.md` advierte que paquetes con nombres parecidos **no son oficiales**: `everything-claude-code`, `opencode-ecc`, `@chil_ntl/ecc-cli`, `ecc-100xprompt-plugin`. Ojo: el nombre antiguo del repo coincide con un paquete npm que ECC declara no oficial. | Alta si alguien instala "por el nombre de siempre". |
| Peso | 328 skills y 72 agentes inflarían el listado de skills y las descripciones de agentes cargadas en cada sesión. | Alta: es justo lo que Julio quiere evitar. |
| Calidad desigual | Varios agentes son genéricos y orientados a web/Postgres/JS (p. ej. `database-reviewer` asume Supabase y RLS; `security-reviewer` usa `npm audit`). Muchas skills son de "community". | Media: hay que adaptar, no copiar. |

**Conclusión:** no instalar ECC. Su valor para Julio está en una docena de reglas, checklists y patrones que caben en sus skills actuales. Varias ideas centrales de ECC ya las tiene (instintos con confianza en `subagent-pool/scripts/instincts.py`, registro de costes en `cost_tracker.py`, consejo de planificación con debate, revisión con chequeo independiente y detección de fallos silenciosos), y en algunos casos su versión es más robusta que la de ECC.

## 3. Hooks de ECC que vale la pena replicar

Julio ya tiene: el hook Stop de `cost_tracker.py`, el plugin `cc-safety-net` (bloqueo de comandos destructivos), notificaciones nativas y `PYTHONUTF8`. No conviene duplicar nada de eso. Lo de abajo son reimplementaciones pequeñas, **no** el runtime Node de ECC.

| Hook de ECC (ID y script) | Qué hace en ECC | Cómo replicarlo | Riesgo |
|---|---|---|---|
| `pre:config-protection` (`scripts/hooks/config-protection.js`) | Bloquea (exit 2) la edición de configs de linters y formateadores ya existentes (`ruff.toml`, `.ruff.toml`, eslint, prettier, biome, stylelint, shellcheck…), para que el agente arregle el código en vez de relajar la regla. Deja crear el archivo la primera vez. `pyproject.toml` queda fuera a propósito. | Regla hookify `event: file`, `action: block`, condición `file_path` con regex sobre `ruff.toml`, `.ruff.toml`, `mypy.ini`, `.flake8`, `.pre-commit-config.yaml`, `pytest.ini`. Mensaje: "arregla el código, no la configuración; si de verdad hay que cambiarla, pídelo". | Bajo. Algún falso positivo cuando sí hay que tocar la config; se desactiva con `enabled: false`. |
| Bloque destructivo de GateGuard aplicado a SQL (`skills/gateguard`, "Destructive Bash Gate") y `skills/safety-guard` | Exige justificar `drop table`, `drop schema`, `alter table … drop column` antes de ejecutarlos. | Regla hookify `event: bash`, `action: block`, regex sin distinguir mayúsculas sobre `\b(drop|truncate|delete\s+from|update\s+\S+\s+set|insert\s+into|alter\s+table|grant|revoke)\b` cuando el comando incluye `sqlplus`, `sql`, `oracledb` o `cx_Oracle`. Hace que la regla de "Oracle solo lectura" se cumpla aunque el modelo la olvide. Complementa a `cc-safety-net`, que mira el shell en general. | Bajo. Puede bloquear un INSERT legítimo en una base de pruebas local; se resuelve con una excepción explícita. |
| Detección de secretos de `pre:bash:dispatcher` (pre-commit quality) y el ejemplo `warn-env-api-keys` de `skills/hookify-rules` | Antes de commitear o escribir, detecta secretos y avisa o bloquea. | Regla hookify `event: file`, `action: block`, condición `new_text` con regex de credenciales embebidas: cadenas de conexión `usuario/clave@host`, `password\s*=\s*['"]`, `sk-…`, `ghp_…`. Mensaje: "credenciales en variables de entorno". | Bajo. Falsos positivos en `.env.example`; se excluyen por ruta. |
| `pre:write:doc-file-warning` (`scripts/hooks/doc-file-warning.js`) | Avisa (sin bloquear) al crear `.md` o `.txt` que no sean README, CLAUDE, CONTRIBUTING, CHANGELOG, LICENSE, SKILL o que estén fuera de `docs/` o `skills/`. | Regla hookify `event: file`, `action: warn`, regex en `file_path` para `\.md$` que no coincida con los permitidos. Refuerza su instrucción global de no crear documentación sin que se pida. | Muy bajo (solo avisa). |
| `pre:edit-write:suggest-compact` (`scripts/hooks/suggest-compact.js`) | Lee el último registro `usage` del transcript y, al pasar ~160k tokens o 50 llamadas, sugiere `/compact` en un punto lógico. | Opcional. Si se quiere, un script Python propio de 30 líneas en PreToolUse (Edit|Write) que lea `transcript_path` y avise por stderr al pasar un umbral. Alternativa sin hook: la tabla de la fila 3 y `/context`. | Bajo-medio: lee el transcript local (sin red). Añade un proceso por cada edición. |
| `pre:compact` (`scripts/hooks/pre-compact.js`) | Guarda estado antes de compactar. | Mejor como regla de comportamiento (fila 3: escribir el plan en un archivo antes de compactar) que como hook, para no copiar el transcript (y posibles datos de Afinia) a otro archivo. | Medio si se replica tal cual, por la persistencia de datos. |

Cómo aplicarlas: con el plugin oficial **hookify** (no está activo en su `settings.json`; viene en `claude-plugins-official`) o como entradas propias en `hooks` de `settings.json` con un script Python local. En ambos casos las reglas deben ser archivos locales que Julio escribe y no reglas que lleguen dentro de un repo clonado. ECC aplica el mismo criterio: desactiva por defecto las reglas hookify que vienen versionadas en git.

## 4. Lo que NO conviene tomar

| Pieza | Por qué no |
